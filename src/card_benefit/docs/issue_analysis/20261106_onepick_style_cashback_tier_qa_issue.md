# ONE PICK·STYLE 캐시백 구간 QA 이슈

## 1. 이슈 요약

QA 항목 `CARD10-021`의 STYLE 영역 캐시백 문항에서, 1만원 결제 시 프로그램이 다음 취지의 답변을 만들거나 LLM 답변을 그 문구로 대체한다.

> 3천원 이상 구간과 1만원 이상 구간에 모두 해당하지만, 어느 캐시백 금액이 적용되는지는 아직 확정되지 않았습니다.

이는 LLM이 만들어 낸 결론이 아니다. 현재 답변 검증 경로가 중복 적용 구간으로 판정했을 때 `fixed_conclusion()`이 `tier_answer()`를 호출해 생성하는 프로그램 문구다.

## 2. 확인한 원문과 등록 데이터

읽기 전용 PostgreSQL 조회로 확인한 상품설명서 메타데이터:

| 항목 | 값 |
|---|---|
| 문서 | `ONE PICK STYLE 하나 체크카드 상품설명서` |
| `card_doc_id` | `20261101_000002` |
| 파일명 | `hana_all/debit/체크_ONEPICKSTYLE하나체크카드_상품설명서(공식PDF,URL추정확인)_15650_20260429.pdf` |
| 문서 URL | `https://m.hanacard.co.kr/leaflet/15/15650_20260429.pdf` |
| SHA-256 | `6ec9641c2e318ce9429a916f5d01c0468ccc3cffb238eb1162a43b280e25c6d2` |
| 페이지·청크 | p.1, `20261101_000012` |

PG의 원문 청크와 `card_source_evidence`를 조회했다. ONE PICK 및 STYLE 모두 같은 표 인용(병합된 표 영역)을 사용한다. 구간 관련 evidence는 `20261101_000034`·`000035`·`000040`·`000041`; 저장 위치는 `start_pos=1565`, `end_pos=1607`이다. 원문은 다음과 같다.

```text
결제 건당 3천원 이상 시 100원 /
결제 건당 1만원 이상 시 500원
```

같은 페이지 청크에는 STYLE의 `일 1회 / 월 10회`, `월 5천원`, ONE PICK의 `일 1회 / 월 30회`, `월 5천원` 표기도 있다. 두 혜택의 규칙 값은 각각 `100 KRW`, `500 KRW`; 최소 결제금액은 `3,000`, `10,000`이며, 두 조건의 `cond_max_amt_excl`은 모두 `NULL`이다.

확인 범위는 PostgreSQL에 보존된 PDF 추출 원문과 근거 위치다. PDF 파일 자체의 시각적 표 레이아웃은 이번 작업에서 별도 렌더링·대조하지 않았다.

## 3. 상위 구간 우선 여부

조회된 원문에는 두 하한과 각 금액이 있지만, “상위 구간 우선”, “가장 높은 금액 적용” 또는 동등한 우선순위 문구는 확인되지 않았다. `cond_max_amt_excl`도 비어 있다. 따라서 현재 증거로 확정 가능한 내용은 두 개의 하한과 캐시백 금액뿐이다.

10,000원 이상 구간이 3,000원 이상 구간을 대체한다는 해석은 일반적인 구간표 관행일 수 있지만, 이는 현재 확인한 원문 명시사항과 구분해야 한다. 이번 문서에서는 그 해석을 데이터 사실로 취급하지 않는다.

## 4. 코드에서 답변이 생성되는 경로

현재 구현의 관련 위치는 `payment_card/db_pipeline_origin_search/card_graphrag.py`다.

1. `rule_selection_open()` (875행)은 같은 대상에 적용되는 두 규칙을 선택 미확정 상태로 판정한다.
2. `rule_conflicts()` (1018행)는 규칙의 최소 결제 금액과 지급값을 구간 후보로 모은다.
3. `tier_applies()` (1041행)는 `amount >= min_amt`이고 상한이 없으면 적용된다고 본다. 10,000원 결제는 3,000원·10,000원 규칙 둘 다 적용된다.
4. `tier_answer()` (1271행)는 연결된 원문에서 구간 관계가 확인되지 않으면 실제 지급액 미확정 문구를 만든다.
5. `fixed_conclusion()` (1293행)은 여러 구간이 적용되는데 결론이 규칙 선택 미확정을 표현하지 않거나 일부 구간만 선택하면 그 고정 문구를 사용한다.
6. `validate_answer()` (1310행)의 구간 검증과 자연어 검증 `answer_text_problem()` (1502행)도 이 후보 구조를 참조한다.

기존 테스트 `payment_card/tests/test_card_graphrag.py`에는 다음 관련 검증이 있다.

- `test_tier_answer_states_confirmed_tiers_briefly`: 중복 적용과 미확정 지급액을 담은 프로그램 문구를 기대값으로 둔다.
- `test_valid_llm_answer_is_kept_for_payment_question`: 같은 미확정 설명을 포함한 LLM 문장을 허용한다.
- `test_wrong_amount_and_condition_relations_are_blocked`: 하한과 지급액을 잘못 짝지은 문장은 차단한다.

따라서 현재 “미확정” 응답은 소스와 테스트가 함께 고정한 동작이다. 다만 “금액이 적용되는지 원문에서 확인되지 않았다”는 표현은 **우선순위 계약을 저장하지 않은 데이터 구조**를 안전하게 반영한 것이며, 사용자 관점에서 정답인지와는 별개 QA 판단이 필요하다.

## 5. 오류와 데이터 표현 문제의 구분

### 답변 품질 이슈

질문이 구간표를 비교하거나 특정 금액의 적용액을 기대할 때, 양쪽 기준이 모두 적용된다는 답은 기대하는 구간 선택을 설명하지 못한다. 이 현상은 결제 금액 10,000원 이상에서 재현 가능하며, LLM 표현과 무관하게 프로그램 검증이 해당 상태를 만든다.

### 원천·모델링 이슈

원문 청크에는 `3천원 이상 → 100원`, `1만원 이상 → 500원`이 있으나 상한·우선순위 필드는 제공되지 않는다. 추출 및 등록 데이터는 두 규칙의 상한을 `NULL`로 보존한다. 따라서 어느 구간이 우선인지 모델이 알 수 없는 상태는 현재 구조와 원문 추출 결과에 맞는다. 이는 원문 값이 유실됐다는 증거는 아니다.

## 6. 수정 대안

| 대안 | 변경 | 장점 | 위험·전제 |
|---|---|---|---|
| A. 현 상태 유지 | 우선순위 근거가 없으면 지급액 미확정 유지 | 원문 밖의 규칙을 만들지 않음 | QA 기대 응답과 맞지 않을 수 있음 |
| B. 원문에서 우선순위 근거 추가 확인 | 공식 PDF 표의 시각적 배열·각주·약관을 검토하고, 명시 근거가 있으면 이를 추출/검증 데이터에 저장 | 해석 대신 출처가 있는 계약을 사용 | PDF 원본 확인 및 검토 승인이 필요 |
| C. 다음 하한으로 `max_amt_excl` 산출 | 3,000~10,000원과 10,000원 이상으로 구조화 | 기존 구간 비교기가 단일 구간을 선택할 수 있음 | 이 사례에선 두 하한만으로 상한을 추론한다. P1 정책은 원문에 없는 상한을 추론하지 않으므로 사용자 승인과 `max_basis` 근거가 필요 |
| D. 답변 문구만 변경 | 적용 여부를 설명하거나 비교 확인 요청으로 표현 | 사용자 메시지가 덜 단정적일 수 있음 | 우선순위가 없는 사실 자체는 해결되지 않으며, 변경 전 QA 문구 검토가 필요 |

권장 순서는 공식 PDF의 시각적 표와 주석에서 상위 금액 우선이 **명시**되었는지 먼저 확인하는 것이다. 명시되지 않았다면 B를 적용하지 않고, A 또는 D 중 제품 답변 정책을 결정한다. 승인 전 코드와 데이터를 변경하지 않는다.

## 7. 회귀 검증 시나리오

- 결제 2,999원: 어느 구간도 해당하지 않아 캐시백 금액을 단정하지 않는다.
- 결제 3,000원: 100원 구간만 해당한다.
- 결제 9,999원: 100원 구간만 해당한다.
- 결제 10,000원: 현재 계약에서는 두 하한을 모두 만족한다. 상위 구간 우선 근거가 승인되기 전에는 검증기가 임의로 500원 단일 지급으로 확정하지 않는다.
- 결제 10,001원: 현재 계약의 겹침 판정이 유지되는지 확인한다.
- STYLE 한도와 횟수: 월 5,000원, 일 1회·월 10회가 ONE PICK 값과 혼합되지 않는지 확인한다.
- ONE PICK 한도와 횟수: 월 5,000원, 일 1회·월 30회가 STYLE 값과 혼합되지 않는지 확인한다.
- `RAW_MATCH`여도 잘못된 구간 관계가 허용되지 않도록 기존 검증을 유지한다.
- 수정안을 선택한 경우, LLM 호출 없이 `validate_answer()`와 `answer_text_problem()` 단위 테스트로 경계값을 검증한다.

## 8. 이번 작업 범위와 미확인 사항

- 코드, 테스트, DB 변경은 적용하지 않았다.
- 원문·규칙·인용은 PostgreSQL 읽기 전용으로 확인했다.
- PDF 파일 자체의 시각적 표 레이아웃 및 우선순위 명시 여부는 아직 직접 확인하지 않았다.
- 공식 상품설명서에 상위 구간 우선 문구가 실제로 있는지 결정하기 전에는 `max_amt_excl`을 추가하거나 테스트 기대값을 변경하지 않는다.
